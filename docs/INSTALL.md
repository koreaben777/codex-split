# 설치 안내

CodexSplit은 Mac에 설치된 공식 ChatGPT(Codex) 앱을 별도 업무 프로필로 실행합니다. 사용자는 자신의 Mac에서 소스로 빌드하고 본인의 업무 계정으로 로그인합니다. 저장소에는 공식 앱이나 다른 사람의 로그인·대화 데이터가 포함되지 않습니다.

## 먼저 준비하기

- macOS의 본인 사용자 계정에서 작업합니다. `sudo`로 설치하지 않습니다.
- [README의 지원 대상](../README.md#지원-대상-앱)을 먼저 확인하세요. `/Applications/ChatGPT.app` 경로뿐 아니라 `com.openai.codex` 서명, `Contents/MacOS/ChatGPT`, 번들 CLI와 `app.asar` 구조가 필요합니다. 이름이 같은 다른 앱이나 `/Applications/Codex.app`은 현재 실행 대상이 아닙니다.
- Xcode Command Line Tools와 Git, `python3`가 필요합니다. GUI 자동 업데이트는 `/usr/bin/python3`를 사용하므로 이 경로도 실행 가능해야 합니다. 최소 macOS·Xcode 버전 및 CPU별 지원 범위는 아직 확립하지 않았습니다. 개발 도구가 없다면 Terminal에서 `xcode-select --install`을 실행하고 설치 창의 안내를 완료하세요. 설치 명령은 누락된 도구를 안내하고 멈추므로, 준비가 끝나면 다시 실행합니다.
- 소스는 본인 Mac의 계속 보관할 폴더에 둡니다. 예: `~/Projects/codex-split`. 동기화·공유 폴더는 피하세요. `/tmp`나 `/var/folders` 같은 임시 폴더는 macOS 경로 별칭으로 검사가 실패할 수 있으므로 사용하지 마세요. 설치한 뒤에는 소스를 이동하거나 삭제하지 마세요.
- 사용할 업무 계정에 로그인할 수 있어야 합니다. 이 도구는 계정을 만들거나 조직의 로그인 정책을 우회하지 않습니다.

## 한 명령으로 설치

저장소를 받은 폴더에서 Terminal을 열고 실행합니다.

```sh
sh scripts/install.sh
```

아직 clone하지 않았다면, 소스를 둘 상위 폴더에서 다음 한 줄을 실행하세요.

```sh
git clone https://github.com/koreaben777/codex-split.git && cd codex-split && sh scripts/install.sh
```

설치 명령은 다음을 순서대로 수행하며, 실패한 단계가 있으면 이후 단계로 진행하지 않습니다.

1. macOS·대화형 Terminal·개발 도구·공식 앱·기존 설치 유무를 확인합니다.
2. 검사 도구를 빌드하고, 공식 앱의 서명과 버전을 검사하여 이 Mac의 앱 버전에 맞춥니다. 지원 조건이 맞지 않으면 중단합니다.
3. 전체 자동 검사와 런처 빌드를 실행합니다. 이 단계에서는 실제 업무 프로필을 열지 않습니다.
4. Terminal 안내를 통해 업무 프로필을 만들고 직접 로그인·종료·재실행을 확인합니다.
5. 공식 앱 버전이 도중에 바뀌지 않았는지 다시 검사합니다.
6. `~/Applications/CodexSplit-work.app`에 런처를 설치하고 완료 경로를 표시합니다.

빌드와 검사에는 시간이 걸립니다. 완료될 때까지 Terminal을 열어 두세요. 다른 설치·업데이트·빌드를 같은 폴더에서 동시에 실행하지 마세요.

## 로그인할 때 할 일

검사·빌드가 끝나면 Terminal이 입력을 요청합니다. **실제 화면의 안내와 순서를 따르세요.**

- `LOGIN work`: 새 업무 프로필을 만들고 로그인 확인을 시작합니다. 새 업무 창이 열리면 안내 시간 안에 클릭하고 공식 앱 화면에서 로그인합니다.
- 업무 창 계정이 맞으면 `confirmed`, 개인 앱의 계정·대화·설정이 그대로라면 `unchanged`를 입력합니다. 다른 계정이나 변화가 보이면 성공으로 답하지 마세요.
- `QUIT` 입력 후 업무 창을 클릭하고, Terminal에 `READY`가 나온 뒤 **그 업무 창에서** Cmd-Q 합니다. 개인 앱을 종료하거나 로그아웃하지 않습니다.
- `REOPEN work`로 다시 열고 로그인 유지 여부와 정상 종료를 한 번 더 확인합니다.

암호·인증 코드·토큰은 Terminal에 입력하지 않습니다. 공식 앱 로그인 화면에서만 처리하세요.

## 설치 후 처음 실행

Finder의 **이동 → 폴더로 이동**에서 `~/Applications`를 열고 `CodexSplit-work.app`을 실행합니다. 자주 쓸 경우 Dock에 추가할 수 있습니다.

처음에는 런처의 안내에 따라 수용 시험을 **두 번** 진행합니다. 각 시험에서 메뉴 막대의 **업무 확인** 메뉴로 업무 계정·개인 앱 무변화·프로젝트 연결 상태를 확인하고 정상 종료 준비를 선택한 뒤, 해당 업무 창에서 Cmd-Q 합니다. 두 번 성공하면 일상 사용 허용에 동의합니다.

이후에는 런처를 클릭하면 업무 창이 열립니다. 일상 사용에는 업무 확인 메뉴가 없으며, 업무 창을 Cmd-Q로 종료하면 런처도 종료됩니다. 설치 과정의 로그인 확인 두 번과 설치 후 런처 수용 시험 두 번은 별개입니다.

## 기존 설치·중단 후 재개

`install.sh`는 **처음 설치 전용**입니다. 기존 런처나 업무 프로필이 있으면 그대로 두고 중단합니다. 자동 초기화·삭제·덮어쓰기는 하지 않습니다.

| 상황 | 다음 행동 |
|---|---|
| 준비 도구 누락 또는 로그인 단계 전 빌드·검사 실패 | 원인을 해결하고 같은 폴더에서 `sh scripts/install.sh`를 다시 실행합니다. |
| 이미 정상 설치해서 사용 중 | 설치 명령을 반복하지 말고 기존 런처를 엽니다. 공식 앱 버전 변경은 [업데이트 안내](UPDATES.md)를 따릅니다. |
| 로그인 필요(`loginRequired`)를 보고하고 정상 종료까지 기록됨 | 정상 로그인 가능한 환경에서 `.build/codex-split-work-setup --resume-setup work`로 재개할 수 있습니다. 허용 가능한 기록인지 도구가 다시 검사합니다. 성공 후 아래 수동 설치의 런처 설치를 진행합니다. |
| 업무 설정 완료 메시지까지 나온 뒤 런처 설치만 실패 | 기존 런처가 없는지 확인하고, 아래 수동 설치의 버전 재확인·런처 설치를 실행합니다. |
| 확인 중 Terminal 종료, 시간 초과, 계정 불일치, 개인 앱 변화, 원인 불명 | 프로필을 삭제하거나 강제 재실행하지 말고 마지막 오류와 중단 단계를 [문제 보고 안내](../CONTRIBUTING.md)에 따라 정리합니다. 임의로 `state.json`을 수정하지 않습니다. |
| 기존 업무 프로필이 다른 위치에 있음 | [기존 프로필 옮기기](#기존-프로필-옮기기)를 따릅니다. |

문제 보고에 계정 토큰, `auth.json`, 대화 내용이나 프로필 폴더 전체를 첨부하지 마세요.

## 수동 설치

설치 스크립트와 같은 핵심 명령입니다. 처음 설치에서는 위의 한 명령 방식을 권장합니다.

```sh
sh scripts/build.sh
python3 scripts/update-work.py --pin-installed
sh scripts/check.sh
.build/codex-split-work-setup --setup work
.build/codex-split update-check work --json
python3 scripts/install-work-update-approved.py --install-new
```

각 명령이 성공한 경우에만 다음 명령을 실행하세요. `--pin-installed`는 업무 프로필이 생기기 전에만 사용할 수 있습니다. 설정을 이미 마쳤다면 이를 다시 실행하지 않습니다. 마지막 버전 검사가 실패하면 앱 버전이 달라졌거나 서명을 확인하지 못한 것이므로 설치를 진행하지 말고 [업데이트 안내](UPDATES.md)를 확인하세요.

## 업데이트와 소스 보관

공식 앱이 업데이트되면 업무 런처가 자동 대응을 제안합니다. 동의하면 보관된 소스와 개발 도구로 새 런처를 빌드·검사하고 교체합니다. 개발 도구와 Python도 계속 필요합니다. 자세한 흐름은 [업데이트 안내](UPDATES.md)에 있습니다.

GitHub의 CodexSplit 코드 업데이트와 공식 앱 업데이트는 별개입니다. `git pull`만으로 설치된 런처가 교체되지는 않습니다. 런처 코드 변경을 설치하는 절차는 [수동 업데이트](UPDATES.md#수동-경로)를 따릅니다.

처음 설치는 `Sources/AppTrial.swift`의 버전·해시 고정값을 변경할 수 있습니다. 자동 업데이트도 이 파일의 고정값을 동기화하고 로컬 커밋을 만들 수 있으며 자동 push는 하지 않습니다. 소스를 갱신하기 전에는 다음으로 로컬 상태를 확인하세요.

```sh
git status --short
git diff -- Sources/AppTrial.swift
```

로컬 변경이 있다면 보존하고 검토한 뒤 커밋·병합하세요. 충돌을 없애려고 고정값을 무조건 덮어쓰면 현재 설치된 앱과 맞지 않을 수 있습니다. 다른 사용자에게는 GitHub 저장소 링크를 공유하며, 본인의 `.build`나 업무 프로필 폴더를 복사해서 배포하지 않습니다.

## 기존 프로필 옮기기

`codex`, `desktop`, `cwd`(선택: `control`) 구조의 기존 CodexSplit 업무 프로필만 대상입니다. 임의의 개인 앱 프로필을 가져오는 절차가 아닙니다. 원본과 대상은 같은 볼륨이어야 하며, 원본과 하위 세 폴더는 본인 소유·권한 `0700`이어야 합니다. 대상 업무 프로필이 이미 있으면 진행하지 않습니다.

먼저 수동 설치의 빌드·버전 고정·전체 검사를 마치고, **업무 설정 명령 대신** 아래 절차를 사용하세요. 업무 앱·런처·관련 helper를 모두 종료한 뒤 실제 절대 경로를 넣습니다.

```sh
.build/codex-split-work-setup --adopt work --from /absolute/path/to/old/work
.build/codex-split update-check work --json
python3 scripts/install-work-update-approved.py --install-new --retire-existing
```

각 명령이 성공한 경우에만 다음 명령을 실행하세요. 같은 볼륨에서 이름 변경으로 옮기고, 이전 `control` 기록은 `~/Library/Application Support/CodexSplit/legacy/`에 보존합니다. 이동 후 로그인 유지 확인 방문 두 번을 수행합니다. `--retire-existing`은 기존 설치 경로의 런처를 legacy 폴더로 옮기므로, 다른 용도의 런처가 그 경로에 없는지 먼저 확인하세요. 설치 후에는 새 런처의 수용 시험도 필요합니다.

공식 앱이 이전 대화의 절대 경로를 사용할 수 있어, 이전 위치에는 새 위치를 가리키는 링크를 남깁니다. **이 링크를 지우면 이전 대화가 열리지 않을 수 있습니다**(`failed to resolve rollout path`). 이전 위치가 공유·동기화 폴더라면 링크를 통한 데이터 접근에도 주의하세요.

부분 실패 시 자동 되돌리기는 없습니다. 이동된 폴더, 이전 위치의 링크, legacy 기록을 먼저 확인하세요. 되돌리려면 업무 앱과 관련 프로세스를 종료하고, 새 `control` 기록을 따로 보존한 뒤 링크 제거와 폴더 이름 변경을 역순으로 수행해야 합니다. 이전 위치와 현재 위치를 확신할 수 없다면 수동 이동·삭제를 보류하세요.

## 선택 사항: 로컬 아이콘

`Assets/WorkIcon/CodexSplit-work.icns`를 두면 런처 빌드에 포함됩니다. 저장소에는 아이콘을 배포하지 않으며, 사용할 자산의 권리는 직접 확인해야 합니다. 업데이트 교체에서는 기존 아이콘을 유지해야 하므로 운영 소스의 해당 파일도 보관하세요.

## 사용 중지·제거

업무 창에서 Cmd-Q하고 런처가 종료된 것을 확인한 뒤 Dock에서 제거할 수 있습니다. `~/Applications/CodexSplit-work.app`을 제거해도 프로필은 삭제되지 않습니다.

`~/Library/Application Support/CodexSplit/`에는 인증·대화와 실행 기록이, `~/Applications/.CodexSplit-work-replacement-*`에는 이전 런처와 교체 영수증이 남을 수 있습니다. `.build/work-updates`에도 후보와 검사 기록이 있습니다. 계속 사용하거나 복구할 가능성이 있으면 이 자료와 소스 폴더를 보관하세요. 전체 삭제·인증 해제·공식 앱 제거를 대신 수행하는 명령은 제공하지 않습니다.

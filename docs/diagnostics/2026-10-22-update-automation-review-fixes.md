# 업데이트 자동 대응 검토 후 수정·검증 — 2026-10-22

## 수정한 동작

1. `main → deployed_source → prepare_source`에서 현재 운영 코드와 설치된 버전 이력을 분리한다. 고정값이 다르면 격리된 baseline에 현재 코드를 복사하고 관리 고정값 블록만 설치 후보에서 가져온다. 원본 변경을 덮어쓰지 않는다. 다음 후보에 checker-only, 실행 내 빌드 재사용, whole-module 컴파일이 모두 포함된다.
2. 교체 중 실패는 영수증·백업 위치를 전달하여 `recovery-required`로 기록한다. 부분 교체를 자동 재시도하거나 설치본이 그대로라고 안내하지 않는다. 복구는 검증 완료 영수증과 설치본·백업·후보·검토 기록을 대조한다. 복구 가능 상태를 신규 배치 허가로 사용하지 않는다. binding 파일은 임시 파일 동기화 후 배타 게시하고, binding 뒤 결과 기록 저장 실패도 대조 후 재시도할 수 있다. 복구 완료 시 실행 상태도 installed로 갱신한다.
3. 알림 시간 초과·OS 오류와 진행 창 실행 오류는 설치 결과를 바꾸지 않는다. 알림 실패로 시작이 중단되거나 설치 성공이 실패로 뒤집히지 않는다.
4. 빌드 전 읽기 전용 사전 검사에서 미해결 업무/설정 기록, 거부 보고, 설치 런처와 현재 구간 불일치를 차단한다. 설치 직전의 잠금·기록·공식 앱·폴더 검사와 전체 시험은 유지한다.

## 실제 경로 확인

- 설치된 런처의 source-root가 현재 운영 checkout과 일치함을 읽기 전용으로 확인했다.
- 설치된 런처의 해시와 일치하는 후보에서 이력을 선택했다: `.build/work-updates/5183925f0fcf450aa50c60476e0ccba7/candidate`.
- 실제 `prepare_source` 함수로 준비한 baseline은 관리 고정값 블록 외 모든 Sources, scripts, Tests, Assets가 현재 작업 폴더와 바이트 단위로 일치했다.
- 공식 앱 읽기 전용 검사 결과: `pinned`. 첫 검사 14.989초, 같은 실행 내 재검사 3.807초. 재검사에서도 공식 앱 검사는 수행했다.

- 원본 AppTrial.swift 바이트와 설치된 업무 런처 해시가 검증 전후 동일했다.
- 운영 스크립트가 여는 `.build/codex-split-update-progress`는 최종 검증 복사본의 빌드 결과로 갱신했다. 이전 보조 실행 파일은 `.build/update-review-before`에 보존했다. 보조 프로그램도 실행하지 않았다.

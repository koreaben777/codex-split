# 업데이트 검사 재빌드 최적화 측정 — 2026-10-22

## 범위

기존 변경을 포함한 작업 소스를 임시 폴더 두 곳에 복사하여, 변경 전후 `inspect`를 각각 연속 두 번 호출했다. 변경 후에는 실제 pipeline과 같은 실행 내 캐시를 공유했다. 공식 앱 검사는 읽기 전용으로 수행했으며 업무 앱 종료·재시작·설치·프로필 변경은 실행하지 않았다.

각 실행은 새로운 Python 모듈과 빈 실행 내 캐시를 사용했다. 컴파일러 모듈 캐시는 첫 측정 후 남겨 두었으며 순서는 전/후, 후/전, 전/후로 교차했다. 매 쌍에서 관측 앱 정보와 기대 고정값이 동일한지 확인했다. 모든 검사 상태는 `review-required`였다.

| 회차 | 변경 전 2회 검사 합계 | 변경 후 2회 검사 합계 |
|---|---:|---:|

중앙값 41.287초 → 11.836초: 29.451초, 71.3% 단축. 이는 업데이트 전체가 아니라 전후 검사 두 번의 구간이다. 첫 회차는 새 임시 폴더의 컴파일러 캐시 준비 비용을 포함한다.

## 유지한 검증

공식 앱 서명·해시·응답 형식 검사와 후보 전체 검사 호출을 유지한다. 첫 검사는 반드시 빌드하고, 같은 pipeline 안에서만 소스·빌드 스크립트·실행 파일 SHA-256이 일치하면 재사용한다. 빌드 실패 또는 빌드 중 소스 변경 시 차단한다.
